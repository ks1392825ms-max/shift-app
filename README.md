# シフト管理（美容室・複数店舗）

美容室のシフトを店舗ごとに管理する Web アプリです（初期は 店舗A・店舗B。店舗は自由に追加できます）。
インストールは不要です。「この端末だけで使う」モード（初期設定）では外部と通信しません。
「共有モード」にすると、管理者どうしで Firebase を通じて同じデータを使えます。

## 使い方（Mac）

1. Finder で `shift-app` フォルダを開く
2. `index.html` をダブルクリックする（Safari か Chrome で開きます）
3. まず「設定」で店舗・スタッフ・勤務パターンを登録し、「シフト表」で入力する

## 店舗ごとの管理

- **店舗は自由に追加・削除できます**（初期は 店舗A・店舗B）。「設定 > 店舗」の「＋ 店舗を追加」から、店舗名・営業時間・定休日・色を決めて追加します
  - 追加した店舗は、専用のスタッフ・シフト・集計・必要人数・**チェックの基準**を持ちます
  - 削除は、在籍中のスタッフがいない店舗だけできます（最後の1店舗は削除できません）。**削除してもその店舗の記録は消えず**、「削除した店舗」から元に戻せます
  - ▲▼ で並び順を変えられます（画面上部の切り替えの順番）
- **営業日・営業時間（カレンダー）**：「設定 > 店舗」の各店舗の「営業日・営業時間を設定（カレンダー）」で、月ごとのカレンダーから設定します
  - **曜日**を押すと、その月のその曜日をまとめて休業にします（もう一度押すと戻します）。毎週の定休日の日は対象外です。毎月ずっと同じ曜日が休みなら、「編集」の定休日（毎週）を使います
  - **日付**を押すと、その日を「通常営業」「休業」「特別営業時間（○:○○〜○:○○）」から選べます。メモ（例：年末年始・棚卸し）もつけられます。◀▶ で月を移れ、年をまたいでも続けて入れられます
  - **曜日ごとの営業時間**：日〜土の営業時間を入れて「保存」します（「月曜の時間を平日に入れる」「土曜の時間を日曜に入れる」で写せます）。保存していない店舗は、今までどおり「編集」の営業時間を全曜日に使います
  - **特別営業時間**：その日だけの営業時間です（くり返しません）。一覧から削除できます。シフト表の日付に「特別」、1日の詳細・確定シフトに時間を出します
  - 曜日ごとの営業時間・特別営業時間を入れた日は、**営業時間の外の必要人数を数えません**（AIシフト作成・人数のチェックとも）。営業時間の外に勤務が入っていれば、チェックの「営業時間外」で知らせます（勤務は変えません）
  - **臨時休業を期間でまとめて追加**：同じ画面の「＋ 臨時休業を追加」で、開始日〜終了日（両端の日を含む）とメモを入れます（カレンダーで入れた休業と同じものです）
    - その店舗だけ、入れた期間だけの休業です（毎年くり返しません）。一覧の「削除」で取り消せます
    - 定休日と同じ扱いで、AIシフト作成は勤務を入れず、シフト表・確定シフト・画像・スタッフの申請画面では「休業」と表示します。スタッフはその日に希望休・有給を出せません
    - すでに入っているシフトは変えません（期間の中に勤務があれば、追加したときに件数を知らせます）
- **画面上部で店舗を選ぶと、すべての画面がその店舗だけの表示になります**（3店舗までは横並びのボタン、4店舗以上は選択メニュー。選んだ店舗は、次に開いたときも同じです）
  - シフト表・1日の詳細・スタッフ別・集計（この店舗）・設定のスタッフ／毎週の社用／必要人数／チェック
- **シフトは、選んでいる店舗の記録として保存されます**（入力シートの見出しにも店舗名が出ます）
  - 所属していない店舗のシフトには入力できません
- スタッフの追加は、選んでいる店舗に追加されます。ほかの店舗のスタッフは、店舗を切り替えてから追加します
- スタッフを別の店舗に移しても、**それまでのシフトは元の店舗の記録として残ります**（元の店舗の、その月のシフト表にも表示されます）
- 以前に入力したシフト（店舗の記録がないもの）は、スタッフの所属店舗のシフトとして扱います（データは書き換えません）
- 集計は「この店舗」と「店舗の比較」を切り替えられます
  - この店舗：在籍スタッフ、延べ出勤人数、**月間勤務時間**、1日平均、社用・有給、人員不足・過多の日、スタッフ別の表
  - 店舗の比較：上の数字を全店舗で並べた表と、日ごとの St／As／計の比較

## 設定（Step1）

| タブ | できること |
|---|---|
| 店舗 | 店舗名、営業時間（30分刻み）、定休日（毎週の曜日） |
| スタッフ | 表示名、所属店舗、役割（スタイリスト／アシスタント）、肩書き、使える勤務パターン、在籍中かどうか、並び順 |
| 勤務パターン | 出勤・退勤（30分単位、15分単位も可）、休憩の長さ、表示名、色、使う店舗 |

- 営業時間と定休日の初期値（9:00〜20:00、火曜定休）は仮の値です。設定画面で変更してください
- 辞めたスタッフは削除せず「在籍中」を外すと、過去のシフトが残ります
- 勤務パターンを削除すると、スタッフの「使える勤務パターン」からも外れます
  （そのパターンしか使えないスタッフがいるときは削除できません）

### スタッフの勤務条件（設定 > スタッフ）

| 項目 | 内容 |
|---|---|
| 職種 | スタイリスト／ジュニアスタイリスト／ジュニアスタイリスト兼アシスタント／アシスタント。一覧には職種名のまま表示し、シフト表の人数は前の2つを St、後の2つを As として数える |
| 雇用形態 | 正社員／パート |
| 新人・戦力外 | 戦力外の人はシフト表に表示するが、St／As の人数・必要人数のチェック・AIの戦力計算には数えない（シフト表では「外」の印） |
| 週休 | 週○日。月曜〜日曜で休みが足りない週を自動チェックで知らせる |
| 月の休日数 | 空欄なら「設定 > チェック」の月の休日数の目安を使う。入れると、この人だけその日数で自動チェックし、AIシフト作成もその日数まで休みを入れる（定休日・固定休・希望休も1日として数える。週休より優先）。例：月曜定休・固定休が月曜の人を月4日休みにするときは「4」（月曜が5回ある月は5日） |
| 固定休 | 必ず休みの曜日と「祝日も休み」。その日に勤務が入ると知らせる |
| この店舗で働く曜日 | 複数の店舗で働く人の、この店舗の曜日（空＝すべて） |
| ほかの店舗の同じ人 | 2店舗で働く人を店舗ごとに登録してつなぐ。同じ日に2店舗に入ると知らせる |
| 備考・ログイン用メール | メールは希望休・有給の申請でスタッフ本人がログインするため（共有モードでは Firebase にだけ保存） |

- 同じ表示名は、同じ店舗の中だけ重ならないようにしています（2店舗で働く人は同じ名前で登録できる）
- 勤務時間がまだ決まっていない人は、勤務パターンを選ばずに登録できます
- 店舗の定休日は、毎週の曜日に加えて「第1・第3火曜」のような指定もできます
- 勤務パターンには「平日用／土日祝用」「早番／遅番」を付けられます（AIシフト作成で使う予定）

### 並び順（設定の「↑」「↓」）

設定で登録・追加する項目は、右の「↑」「↓」で表示の順番を変えられます。変えた順番は保存され、再読み込みしても残ります。

| 項目 | 順番の単位 |
|---|---|
| 店舗 | 全体で1つ（画面上部の店舗の切り替えもこの順） |
| スタッフ | 店舗ごと |
| 勤務パターン | 店舗ごと（「全店舗共通」のパターンも店舗ごとに別の順番にできる）。シフト入力の選択肢・スタッフの勤務パターンの選択肢もこの順 |
| 毎週の社用 | 店舗ごと |
| 必要人数の時間帯 | 店舗ごと・平日／土日祝ごと（表示の順番だけで、チェックの結果は変わりません） |

- まだ並び替えていない一覧は、今までどおり時刻順・曜日順です。並び替えたあとに追加した項目は、一番下に入ります
- 「祝日」と「削除した店舗」は、日付順などの決まった順番のままです
- 順番はバックアップファイルにも入ります（共有モードでは Firebase に保存）

## 勤務時間の設定（設定 > 勤務パターン・スタッフ）

- **出勤・退勤は30分単位**（8:00、8:30、9:00 …）。「15分単位で選ぶ」に切り替えると、8:15・8:45 なども選べます
- 勤務パターンは「**この店舗専用**」か「**全店舗共通**」として保存します（以前からのパターンは全店舗共通）
  - 画面に出るのは、表示中の店舗で使えるパターン（その店舗専用＋全店舗共通）だけです
- 「**よく使う勤務時間からまとめて追加**」で、8:00〜17:00、8:30〜17:30、9:00〜18:00、9:30〜18:30、10:00〜19:00 などを選んでまとめて登録できます
- スタッフごとに「使える勤務パターン」を選びます。さらに「**曜日ごとのいつもの勤務**」（例：月〜金 9:00〜18:00、土 10:00〜19:00、日 休）を設定できます
  - シフト表の「**曜日の設定を反映**」で、**未入力の日だけ**にいつもの勤務が入ります（入力済みの日・定休日は変えません）
  - マスの入力シートでは、その曜日のいつもの勤務に「いつも」の印が付き、先頭に並びます
- 30分ごとの人数は30分の枠で数えます。15分単位の勤務は、その30分をすべて勤務しているときに数えます（例：9:15 出勤の人は 9:30 の枠から）
- 給与（時給）の計算はしません

## シフト表

- 日付が縦、スタッフが横。◀ ▶ で月を、画面上部で店舗を切り替えます
- マスをタップすると、次の4種類から選べます
  - **通常勤務**：そのスタッフに登録した勤務パターンから選ぶ
  - **通常休**（休）／**有給**（有）
  - **社用**（社）：出勤するが予約は受けない日。時間は勤務パターンから選ぶ
  - 1回選ぶと入力の画面が閉じます。「選んだら次の日へ進む」をオンにすると、1か月分を続けて入力できます（オンにしたことはこのブラウザで覚えます。次の日へ進むときは「12/29 を『休』にしました → 12/30 を入力中」と表示します）。「未入力に戻す」で空欄に戻せます
- 入力・変更・未入力に戻したあとも、シフト表のスクロールの位置（縦・横）と、選んでいたマスはそのままです（共有モードで、保存した内容やほかの管理者の変更が届いて画面が作り直されたときも同じ）。タブを移ったときや、月・店舗を切り替えたときは、一番上から表示します
- 右側の St／As／計 は、その日に**通常勤務**のスタイリスト・アシスタント・合計の人数です（社用の人は含めません）
- 下の行は、スタッフごとの月の勤務・社用・休・有・未入力の日数です
- 店舗の定休日は斜線で表示し、何も入れなければ通常休として数えます
- 休憩・社用時間が設定されている日は、マスの右上に点が付きます
- **社用予定**（店舗を離れる時間）がある日は、勤務の下に「**社 13-15**」と表示します（濃い斜線の「社」の印。幅の広い画面では「外部講習」などの内容も出します）。2件以上ある日は「＋1」。全部の時間と内容は、マスを押すと見られます（PCはマスにマウスを乗せても見られます）
- **スタッフの列は、名前の見出しをドラッグして左右に並べ替えられます**（スマートフォンは見出しを長押ししてから動かす。キーボードは見出しを選んで Alt＋←／→）
  - 並び順は店舗ごとに保存され、再読み込みしても残ります（共有モードでは Firebase の店舗の記録に保存。バックアップファイルにも入ります）
  - **シフト表の表示の順番だけ**です。設定（スタッフ）の「↑」「↓」の順番、AIシフト作成、集計・出力・確定シフトの順番は変わりません
  - 「並び順を元に戻す」で、設定（スタッフ）の並び順に戻せます。あとから追加したスタッフは右端に並びます

## 社用予定（日付を指定した社用）

外部講習・店舗間の移動など、**勤務時間の中で店舗を離れる時間**を、スタッフ・日付ごとに登録します。

- シフト表で、**通常勤務のマスを押す**と、入力シートの「社用予定」に、その日の一覧と入力欄が出ます（「1日の詳細」でスタッフの名前を押しても同じです）
- 登録する項目：開始時間・終了時間（30分刻み）・**社用内容**（外部講習／店舗間の移動／会議・ミーティング／撮影・SNS業務／買い出し／その他から選ぶ）・詳細（任意・30文字まで。例：カット講習）・備考（任意・50文字まで）
- 同じ日に複数登録できます。一覧の「編集」で変更、「×」で削除（確認あり）
- 決まり
  - 社用予定は**勤務とは別に保存**します。登録しても、勤務時間・休日・AIシフト作成・集計の日数は変わりません
  - 社用時間は、**店舗で通常業務ができない時間**として、30分ごとの予約可能人数から除きます（今までの社用時間と同じ）
  - 勤務時間の外・時間が重なる予定・勤務のない日には**登録できません**（理由を表示します）
  - あとから勤務を休みや別の勤務パターンに変えて、社用予定が勤務時間の外になったときや、毎週の社用と重なったときは、自動チェックの「社用予定」で知らせます（社用予定も勤務も自動では変えません）
  - 確定した月は、確定を取り消すまで登録・変更・削除できません
- 見られる人：**オーナーだけ**（共有モードでは Firebase の businessTimes。Firestore のルールで、スタッフ・幹部は自分の店舗の分も読めません）。スタッフ・幹部に見せる確定シフトには入れません
- 以前に登録した社用時間（メモだけのもの）は、そのまま残り、メモを内容として表示します

## 1日の詳細

シフト表の**日付をタップ**すると開きます（マスの入力シートの「休憩・社用時間を設定」からも開けます）。

- **タイムライン**：スタッフごとの勤務・休憩・社用時間を30分単位の帯で表示します
- **30分ごとの人数**：St／As／計と、人数から除いた人（休憩・社用）を表示します
  - その30分をすべて通常勤務している人を数えます（例：9-18 の人は 9:00〜17:30 の枠）
  - 休憩・社用時間に少しでも重なる人は除きます
- **スタッフの名前をタップ**すると、その日の休憩と社用予定を追加・編集・削除できます（30分刻み・勤務時間の中だけ。社用予定は上の「社用予定」と同じ）
  - 休憩は必要な日だけ設定します。設定しない日は、時間帯別の人数から除きません
  - 毎週の社用時間は「この日だけ取り消す」ができます
- ◀ ▶ で前後の日を、画面上部で店舗を切り替えます

## 毎週の社用時間（設定 > 毎週の社用）

- 例：高橋さん 毎週水曜 14:00〜16:00。有効期間（開始日・終了日）も設定できます
- その日の勤務時間と重なる部分だけ反映し、**休みの日は無視**します

## 必要人数（設定 > 必要人数）

- 店舗ごと ×「平日」「土日祝」ごとに、時間帯（30分刻み）とスタイリスト・アシスタントの**最低人数・上限**を設定します
  - 上限は空欄なら「上限なし」（人員過多のチェックをしない）
  - 設定していない時間帯は、人員不足・過多のチェックをしません
- 土曜・日曜・祝日は「土日祝」の設定を使います
- **特定の日だけの上書き**は、1日の詳細画面の「この日の必要人数」で行います
  - 「この日だけ個別に設定」：その日だけの時間帯と人数にする
  - 「平日／土日祝の設定を使う」：その日だけ区分を入れ替える
  - 「元に戻す」：設定どおりに戻す

## 祝日

- 国民の祝日・振替休日・国民の休日を、アプリが自動で判定します（インターネットには通信しません）
- 「設定 > 必要人数」の下で、祝日として扱わない日（チェックを外す）や、追加の休日（例：年末年始）を設定できます

## 自動チェック

シフト表の上の「△ チェック ◯件」を押すと、種類ごとの一覧が開きます。項目を押すと、その日（またはマス）へ移動します。

| チェック | 内容 | 表示 |
|---|---|---|
| 人員不足 | 30分ごとの予約可能人数が最低人数より少ない（St・As別） | 右側の人数に **△**、足りない役割の数字に色 |
| 人員過多 | 上限より多い（上限を設定した時間帯だけ） | 右側の人数に **＋** |
| 連勤 | 連続勤務が上限を超えた（終日社用も出勤。月をまたいでも数える） | マスに色の枠 |
| 月の休日数 | 通常休が目安より**少ない** | 下の「休」の数に △ |
| 労働時間 | 1日・1週（月曜〜日曜）の実働が目安を超えた | マスに色の枠 |
| パターン外 | スタッフに登録していない勤務パターンが入っている | マスに色の枠 |
| 早番0人 | 営業日なのに、出勤している人（人数に数える人）が全員遅番（早番の勤務パターンを使う人がいる店舗だけ） | 一覧だけ |
| 早早・遅遅 | 前日も勤務で、同じ番が続いた（休みを挟んだら数えない。早番・遅番の両方を使える正社員だけ。パートは含めない） | マスに色の枠 |
| 社用予定 | 社用予定が勤務時間の外にある・社用予定どうしや毎週の社用と重なる・勤務のない日（休み・未入力・終日社用）に社用予定が残っている | マスに色の枠（休み・未入力の日は一覧だけ） |
| 週のシフト休 | 正社員（AIシフト作成と同じ人）で、月曜〜日曜の週のシフト休（通常休・定休日。有給は数えない）が「平日の週のシフト休」より少ない（未入力の日がある週は数えない） | 一覧だけ |
| 月の連休 | 同じ人で、シフト休が2日以上続く所が「月の連休」の回数より少ない（未入力の日がある月は数えない） | 一覧だけ |
| 未入力 | 何も入っていない日（スタッフごとの日数） | 一覧だけ |

- 実働＝勤務時間−休憩（休憩の時刻を設定した日はその時間、ない日は勤務パターンの休憩の長さ）

## 月のタイムライン（シフト表の上の「月のタイムライン」）

- 1か月分の、30分ごとの人数を日ごとに並べて見られます（見るだけで、データは変わりません）
- 1日を2段で表示します：上の段がスタイリスト（St）、下の段がアシスタント（As）の人数。色が濃いほど人数（St＋As）が多い時間です
- 必要人数（設定 > 必要人数）に足りない時間は、足りない方（St か As）の数字を赤くします。右端に、その日の不足の枠の数、上に月の合計を出します
- 人数の数え方は「1日の詳細」と同じです（休憩・社用中・戦力外の人は数えません）
- 定休日・臨時休業（勤務の人がいない日）と、まだ誰も入力していない日は1行で表示します
- マスを押すと、その時間の St・As の人数と必要人数を画面の下に出します。日付を押すと、その日の「1日の詳細」を開きます（「‹ 月のタイムライン」で戻れます）
- スマートフォンでは、表を枠の中で横にスクロールできます（日付と St/As の列は左に残ります）

## 出力（シフト表の上の「出力」）

- **画像を保存（PNG）**：1店舗1か月を縦長の1枚に。Mac はダウンロード、iPhone は共有メニュー（LINE・写真に保存など）。長い名前は2行に、社用予定は勤務の下に出します
- **印刷・PDF（A4横）**：印刷の画面で「PDFとして保存」を選ぶと PDF にできます
  - 列の幅と文字の大きさ（8〜7pt）を自動で決めます。勤務時間・名前は途中で切りません（名前は折り返します）

  - 社用予定が多くて表が次の紙に続くときも、店舗名・月・日付・スタッフ名の見出しを毎回出します
  - 印刷には、画面下のメニューや操作ボタンは出ません
  - 印刷の画面が開かなかったとき（Chrome は、続けて何度も印刷すると、読み込み直すまで黙って無視することがあります）は「ページを読み込み直してから、もう一度」と案内します。表を作る途中で失敗したときは、理由を画面の下に出します

## データの保存・バックアップ（設定 > データ）

- データは**開いたブラウザの中**（`shift-app-data` という名前）に保存されます
  - Safari と Chrome、Mac と iPhone では、それぞれ別のデータになります
  - 家計簿アプリとは別の名前なので、同じブラウザで開いても混ざりません
- **同じアプリを2つのタブで開いていても、古い内容で上書きしません**（先に保存された内容を読み込み直します）
- **バックアップを保存**：`shift-backup-日付.json` を保存します。Google Drive や iCloud Drive にも置いておくと安心です
- **バックアップを読み込む**：
  - **合体する（おすすめ）**：この端末とファイルの両方の入力を残します。同じ記録は、あとから変更したほうを残します
  - **丸ごと置き換える**：ファイルと同じ内容にします。直前の状態は「復元を取り消す」で戻せます
- バックアップしていない変更があると「⚠ バックアップしていない変更があります」と表示されます

1. 片方の端末で「バックアップを保存」→ Google Drive などに置く
2. もう片方の端末で「バックアップを読み込む」→「合体する」

## 共有モード（管理者で共有・設定 > データ）

管理者4人が、同じシフトのデータを見て編集できるようにする仕組みです。データは Firebase（Google のサービス。保存場所は東京）に置きます。

- **端末ごとに選びます。** 初期設定は「この端末だけで使う」で、今までどおり通信しません。
- 公開 URL（https://〜.github.io/shift-app/）で開き、設定 > データ >「共有モードに切り替える」を押すと、ログイン画面になります。
- **ログイン用のURL**：公開 URL の末尾に `?login` を付けた URL（https://〜.github.io/shift-app/?login）を開くと、すぐにログイン画面になります（スタッフに送る用）。
- **ログイン**：メールアドレスとパスワードを入れて「ログイン」。
- **初めての方・パスワードを忘れた方**：ログイン画面の「初めての方・パスワードを忘れた方」→ メールアドレスを入れて「メールを送る」→ 「パスワードの再設定」のメールが届く → リンクを押す（スマホ・パソコンのどちらでも）→ 開いた画面で新しいパスワード（8文字以上）を入れて「保存」→ アプリに戻って、メールアドレスとパスワードでログイン。
  - パスワード再設定メールは、1日に送れる数が多いメールです（ログイン用リンクのメールは、無料のプランでは1日に送れる数がとても少ないため）。
  - **まだ一度もログインしたことがない人**には、このメールは届きません。送ったあとの画面の「初めてログインする方はこちら」から、ログイン用のリンクを送ります（開くと、その場でパスワードを決めます）。
  - パスワードを決める（決め直す）と、ログイン中のほかの端末は1時間ほどでログアウトされます（新しいパスワードでログインし直します）。
  - ログイン用のリンクでログインしたときは、**必ずその場でパスワードを決めてから**アプリに入ります（決めるまでは、開き直しても同じ画面）。まだログインしたことのない人のアドレスで、ほかの人が先にパスワードを決めていた場合も、本人が決めたパスワードで上書きされます。
  - メールの確認が済んでいないアカウント（パスワードだけで作られたもの）では使えません（アプリでも、Firebase のルールでも止めます）。
- ログイン中にパスワードを変えたいときは、「設定 > データ」（幹部・スタッフはそれぞれの画面の下）の「パスワード」→「パスワードを決め直す（メールで確認）」（パスワード再設定メールが届きます）。
- Firebase のアカウント（uid）は、メールのリンクでログインしていたころと同じです。パスワードを足しても、権限・店舗・データはそのままです。
- ログインできるのは、Firebase の管理画面で `access/admins` に登録した管理者と、管理者が「設定 > スタッフ」でログイン用メールを登録したスタッフだけです。スタッフは自分の情報と申請だけを読めます。未ログインの人は何も読めません（`firebase/firestore.rules` のルール）。
- 画面の上には、アプリのアイコンと同じロゴ（横4×縦3のマス）・SHIFT・小さな RENASCOR. を出します（11/13〜・v43）。ログイン中は、ロゴの濃いマス3つの色と横の名札（色の点つき）で、誰としてログインしているかが分かります：**管理者＝オレンジ**、**幹部＝赤**（「自分の申請へ」を押すと名札は「幹部（自分の申請）」）、**スタッフ＝白**（細い灰色の線）。ログインの前と「この端末だけ」モードでは、濃いマスは灰色で、名札は出ません。スタッフ・幹部の画面には、メールアドレスを出しません（アカウントの欄は「スタッフとしてログインしています。」など）。スタッフの上のカードには、時間帯のあいさつ（おはようございます・こんにちは・おつかれさまです）を出します。
- 共有モードの間は、画面上部に「共有中」と表示されます（幅の狭いスマホでは、管理者の名札があるときは省きます）。ほかの管理者の変更は、自動で反映されます。電波がないときに入力した分は、つながったときに送られます。
- **端末のデータは、共有モードの間も消えず、書き換えもしません。**「この端末だけで使う形に戻す」で、いつでも元のデータに戻れます。
- 共有モードでも「バックアップを保存」「合体する」が使えます。ほかの管理者のデータまで消してしまわないよう、「丸ごと置き換える」と「復元を取り消す」は使えません。

### 簡単ログイン（PINコード・顔認証/指紋認証）

一度ログインした端末では、アプリを開くたびにメールでログインし直す必要はありません（ログイン状態は端末に残ります）。そのうえで、端末を手に取った人が勝手に開けないよう、**ロック**をかけられます。

- **設定**：ログインしたあとに「簡単ログインを設定しますか？」が一度だけ出ます。あとからは、オーナーは「設定 > データ」、幹部・スタッフはそれぞれの画面の下の「簡単ログイン（この端末）」で設定します。
  - 4桁のPINコード（「1111」「1234」のような番号は使えません）
  - 対応する端末では、顔認証・指紋認証も登録できます（Face ID・Touch ID・Android の指紋など。ブラウザ標準の WebAuthn）。使えない端末では、PINコードだけになります
- **ロックする時**：アプリを開いたとき、ほかのアプリを5分以上使ってから戻ったとき。解除すると、元の画面に戻ります。ロックを外すまでは、権限の確認もデータの読み込みもしません。
- **間違えたとき**：5回続けて間違えると30秒待ち（そのあと間違えるたびに倍）。合計10回で、その端末の簡単ログインを解除してログアウトします（メールでログインし直す）。PINを忘れたときも、ロックの画面の「PINを忘れたとき」から、メールでログインし直せます。
- **保存のしかた**：PINコードはそのまま保存しません（PBKDF2 で元に戻せない形にして保存）。顔認証・指紋認証は、端末に作った鍵の番号と公開鍵だけを保存し、解除のたびに署名を確かめます。どれも**その端末だけ**に、ログインした人と結びつけて保存します（Firebase には送りません）。
- **ログアウト**すると、その端末の簡単ログインも解除します。別の人がその端末でログインしたときも、前の人の設定は消します。
- **共用の端末**：「この端末では使わない（共用の端末）」を選ぶと、その端末では案内もロックも出ません（ログアウトしても、この設定は残ります）。
- 簡単ログインは「端末の鍵」です。Firebase のログインと、管理者・幹部・スタッフの権限、店舗の制限（`firebase/firestore.rules`）はそのままで、PINコードがログインの代わりになることはありません。

### 変更申請（承認済みの希望休・有給の取り消し・日付の変更）

承認済みの希望休・有給は、スタッフが自分で消したり変えたりできません。変えたいときは**変更申請**を出します。

1. **スタッフ**：申請画面の「希望休の状況」「有給希望の状況」、または「今月の承認済みの休み」で、承認済みの行の「変更申請」を押し、「取り消し」か「日付の変更」（同じ月の日付）を選んで送ります（理由は任意・50文字以内）。受付期間に関係なく、いつでも出せます。申請中のものは取り下げられます。同じ申請への変更申請は3回まで（2回目・3回目は前の回が却下のときだけ）
2. **判断**：担当店舗の幹部（受付期間の翌月分だけ）か、オーナーが「承認」「却下」（理由は必須）。幹部自身の変更申請はオーナーが判断します。判断の決まりと履歴は、希望休・有給と同じです
3. **反映（オーナーだけ）**：申請タブの「変更申請」で、承認済みのものの「シフト表に反映」を押すと、
   - シフト表：元の日の「休み／有給」を空欄に戻し、日付の変更なら新しい日に「休み／有給」を入れます（新しい日に勤務が入っていれば確認します）
   - 申請の記録：元の申請を「取り消し済み」にし、日付の変更なら新しい日の承認済みの申請を作ります。変更申請には「反映済み（反映した人・日時）」が付きます。どれも判断の履歴に残ります
   - 確定済みの月は、先にシフト表の「確定を取り消す」が必要です
- 確定の前の確認には、申請中の変更申請と、承認済みでまだ反映していない変更申請も出ます

- スタッフの画面：いちばん上に「○月分　休み ○日 確定／有給 ○日 申請中」の1行。受付期間外は「次の受付：○月○日から」

**AIシフト作成の追加（11/8〜・v34）**：

**毎日そろえる出勤時刻（11/5〜）**：設定 > チェックの「毎日そろえる出勤時刻」（平日・土日祝。初めは平日 9:00・10:00／土日祝 8:00・9:00。6:00〜13:00 の30分ごと）。AIシフト作成は、必要人数を満たしたうえで、その時刻に出勤する人が毎日最低1人ずつになるように勤務パターンを選ぶ（不足が増える・ほかの時刻が0人になるときは変えず、お知らせに理由を出す。その時刻に始まるパターンを誰も使えない時刻はそろえない）。シフト表のチェックでも、その時刻に出勤する人がいない日を知らせる。

**パートの休みの日数を決めない・いつもの勤務の社用（11/5〜）**：スタッフの設定で、パートの人は「休みの日数を決めない（人数が足りない日に入れる）」を選べる（offFlex。週休・月の休日数は使わない）。AIシフト作成は、ほかの人を入れたあと、必要人数が足りない日・時間帯にだけ入れ、入れない日は休み。働く曜日・固定休がなくても対象。「曜日ごとのいつもの勤務」で「社用（終日）」（business:勤務パターンID）を選べ、曜日の設定を反映・AIシフト作成でその曜日に社用が入る（店舗の人数に数えない）。

**シフト表の上のボタン（11/5〜）**：よく使う「チェック」「AIで作成」（黒）「シフトを確定」（太い線）を1行に並べ、時々使うものは「⋯ そのほか」のメニュー（出力・月のタイムライン・曜日の設定を反映・自動作成を取り消す・欠勤・急な休み・並び順を元に戻す）。パソコンの幅では「出力」「月のタイムライン」も外に出す。スマホは2段（チェック＋⋯／AIで作成＋シフトを確定）。対応中の欠勤・急な休みは外に出す。

**その日だけの勤務時間（11/5〜）**：日別の画面のタイムラインで、勤務の棒を長押し（0.5秒）すると動かせる。真ん中をつかむと全体がずれ、左右の端をつかむと開始・終了だけが変わる（30分ごと）。離すと確認してから保存（シフトの start・end。勤務パターンは変えない）。名前を押して出る編集の画面の「勤務時間」でも変えられ、パターンの時間に戻せる。シフト表のマスは時間（例：10-19）と左上の点、集計・印刷・出力・確定シフトの写しもその時間。マスで勤務パターンを選び直すと消える。確定済みの月は変えられない。休憩・社用の予定（日付指定）がはみ出すときは保存しない。古い版のアプリでは、パターンの時間で見える。

**受付期間（11/5〜）**：オーナーが「申請」→ タブ「受付期間・上限」で、開始日（1〜28日）と終了日（開始日〜28日、または月末）を選んで保存（全店舗共通。初めは25日〜月末）。その期間だけ、スタッフが翌月分の申請・取り消しを、幹部が判断と自分の休み・社用の登録をできる。期間の外はオーナーだけ。Firestore のルールも同じ設定（settings/requests の openDay・closeDay）で判断する。**ルールは settings/requests があることが前提**（ないと申請は断られる）。幹部が自分で入れる休みの判断の履歴は、別の書き込みで残す（ルールの計算の回数の上限のため）。

**日付ごと（11/5〜）**：幹部の画面とオーナーの申請の画面に、タブ「日付ごと」。縦にその月の日付と曜日（土曜は青・日曜祝日は赤・定休日は「定休」）、横にその日に申請したスタッフの名前と状態の札（希望休の申請中＝黄・承認＝緑・非承認＝灰／有給＝青／社用で不在＝紫）。日付の横に休む人数（非承認を除く）。選んでいる店舗と月だけ・取り消し済みは出さない・見るだけ（判断は「希望休」「有給」のタブ）。

オーナーが Firebase の管理画面で、コレクション `managers` に「ドキュメント名＝メールアドレス（小文字）、`storeIds`＝担当店舗のID の配列、`deleted`＝false」を作ると、その人はログインすると**幹部の画面**になります（アプリからは登録・変更できません）。

| タブ | できること |
|---|---|
| 希望休・有給 | 担当店舗の申請を、スタッフ別・月別に見る。**受付期間（25日〜月末）の翌月分だけ**、「承認」「却下」（理由は必須・50文字以内）「申請中に戻す」ができる。変えられるのは**申請中のものと、自分が判断したものだけ**（自分の申請・ほかの幹部やオーナーが判断したものは、理由を表示してボタンを出さない）。判断した人・日時・却下の理由を表示。有給の日付の変更はできない（オーナーだけ） |
| 判断の履歴 | 担当店舗の、誰が・いつ・どう判断したか |
| 確定シフト（担当店舗） | 担当店舗の、確定・公開済みのシフトを、**管理者のシフト表と同じ見た目**（日付の曜日の色・祝日・定休、スタッフ名と St／As の印・肩書き、勤務「9-18」・休・定休・社用のマス、右側の St・As・計の出勤人数）で見るだけ（押しても何も変わらない）。中身は公開用の写しだけなので、勤務パターンの色は出さず、勤務のマスは1色。作成中のシフト・担当外の店舗のシフトは表示されない |

- 担当外の店舗の申請・確定シフト、作成中のシフト・設定は、画面に出ないだけでなく、Firestore のルールでも読めません
- 幹部がスタッフとしても登録されていれば、「**自分の休み・社用を入れる**」から、自分の分を入れられます（11/5〜）
  - **休み**：日を選んで「休みを登録」→ **承認なしで、その場で確定**（承認済み・判断した人は本人・役割は幹部。判断の履歴に「幹部が自分で登録」）。決まりはスタッフの希望休と同じ（受付期間の25日〜月末に翌月分・月の上限まで・定休日は不可）
  - **社用で不在**：日を選び、内容（外部講習／店舗間の移動／会議・ミーティング／撮影・SNS業務／買い出し／その他）と詳細（任意・30文字まで）を入れて「登録」→ その場で確定（1日まるごと・日数の上限なし・受付期間だけ。休み・有給の日とは重ねられない）。共有モードでは Firebase の businessDays
  - 自分で入れた休み・社用は、受付期間の間は「申請の状況」の「取り消す」で取り消せます。オーナーは、いつでも取り消せます
  - **有給**は、今までどおりオーナーが承認します（自分の有給の申請も、オーナーが判断します）
  - オーナーのシフト表：自分で登録した休みは「希」、社用で不在は「不在」の印（シフトのデータは変えない）。AIシフト作成では、休みの日は「休み」、社用で不在の日は「社用」（その人のいちばん上の勤務パターン・店舗の人数には数えない）を入れます

### 希望休・有給の申請（共有モード）

**画面の並び（11/5〜）**：いちばん上に「あいさつ」（「スタッフ」・名前「〇〇 さん」・店舗・「受付中　○月分・○月末まで」／「受付期間外　○月分は○月25日から」）→「休み希望」「確定シフト」のタブ → カレンダー（説明は1行「休みたい日を押して、「希望休を送信」」「あと○日選べます（今 ○／○日）」。長い説明は「くわしい説明」を押すと開く）→「申請の状況」（希望休・有給希望・今月の承認済みの休み・変更申請）→「アカウント・この端末の設定」（ログイン中のメール・簡単ログイン・パスワード・ログアウト。ふだんは閉じてある）。店舗を選ぶ欄は、所属が2店舗の人だけに出ます（名前を選ぶ欄はなし）。送信のボタンは、日を選んでいないときは「日を選んでください」、選ぶと「希望休を送信」、送ったあとは「送信済み」です。

**スタッフ**（スマホ）：管理者が「設定 > スタッフ」でログイン用メールを登録した人が、メールのリンクでログインすると申請画面が開きます。

- **ログインの案内**：オーナーが「設定 > スタッフ」でスタッフを開くと、ログイン用メールを保存済みの人には「ログイン用のURL」と「URLをコピー」「パスワード設定用のメールを送る」が出ます（共有モードのときだけ）。
  - URL を LINE などで送る → スタッフが開く → メールアドレスを入れる → 届いたリンクを同じ端末で開く
  - 「パスワード設定用のメールを送る」→ 保存済みのアドレスに Firebase からパスワード再設定メールが届く → スタッフが開いて、新しいパスワードを決める（まだ一度もログインしたことがない人には届かないので、ログイン用のURLを送り、「初めての方・パスワードを忘れた方」から始めてもらう。送ったアドレスはオーナーの端末に覚えない。入力欄を書き換えて保存していないときは送らない）

- 店舗を選択（2店舗に所属する人だけ）→ スタッフ名（本人だけ）→ 翌月のカレンダー
- **希望休**：日付を押して選び、「希望休を送信」。通常は1か月2日まで（3日目を押すと「通常の希望休は2日までです。…」と表示）。**希望休は承認制**です（平日・土日祝とも）。状況の一覧に「申請中」「承認済み」「却下（理由つき）」が出ます。カレンダーの印は、希?＝申請中、希＝承認、×＝却下
- **承認済みの希望休は、自分では外せません**（変更が必要なときは変更申請）。**却下された日**は「希望休の状況」で消すと、上限の範囲で別の日を申請し直せます（却下の日も、消すまでは日数に数えます）
- **有給希望**：「有給希望」に切り替えて日付を選び、申請。オーナー（または担当店舗の幹部）が承認すると確定します。取り下げられるのは申請中のものだけです（承認済みは変更申請）。却下されたときは理由が表示されます
- 受付は**毎月25日〜月末に翌月分**（日本時間）。定休日は選べません
- 押せない日（受付期間外・定休日・臨時休業）は薄い色で表示し、押すとカレンダーのすぐ下に理由が出ます（例：「今は受付期間外です。○月分は○月25日から受け付けます。」）
- **土日祝は原則出勤**です。土日祝の希望休は、冠婚葬祭など、やむを得ない事情のときだけ出します。**ほかの希望休と同じく承認が必要**で、承認されるまで休みは確定しません（選ぶと案内が出ます）。ただし、年次有給休暇など法令上の休暇の申出は、この限りではありません（有給は「有給希望」から申請します）
- ほかのスタッフの名前・申請・シフトは見えません（Firestore のルールでも止めています）

**管理者**：下のタブの「申請」

| 画面 | できること |
|---|---|
| 希望休一覧 | 月・店舗ごとに、スタッフ別の希望休（日ごとの状態と、判断した人・日）と、未提出の人。「承認」「却下」（理由は必須・50文字以内・スタッフにも表示）「申請中に戻す」。オーナーは、いつでも・誰の判断でも変えられる。判断してもシフト表は変えない（承認済みの分は AIシフト作成で休みになる） |
| 有給申請一覧 | 承認・却下（理由は必須）・申請中に戻す・日付の変更（申請中のものだけ・オーナーだけ）。承認してもシフト表は変えない（承認済みの有給は、AIシフト作成で空いているマスに「有給」として入る） |
| 判断の履歴 | 誰が・いつ・どの申請を・どう判断したか（日付の変更も）。書き換え・削除はできない |
| 希望休の上限 | 全員の初期の上限（2日）と、スタッフ別・月別の上限（夏休み・冬休みなど）。オーナーだけが変えられる |

- シフト表では、スタッフの希望休の日に印が付きます：「希」＝承認済み、「希?」＝申請中（却下は印なし。表示だけで、シフトは変わりません）
- **確定の前の確認**：「シフトを確定」を押すと、申請中のままの希望休・有給と、承認済みなのにシフト表が違う日（希望休なのに勤務・有給なのに「有給」でない）の一覧が、確認の文に出ます
- 申請のデータは Firebase にだけ保存します（この端末には保存しません）

### AIシフト作成・シフト確定（シフト表の上のボタン）

**AIで作成**：その店舗・その月の**空いているマスだけ**を埋める案を作り、確認してから入れます（外部のサービスにはデータを送りません。アプリの中で計算します）。

1. 必ず休み：**承認済みの希望休**（平日・土日祝とも）、**承認済みの有給**（空いているマスに「有給」を入れる）、固定休（曜日・祝日）。**申請中・却下のものは休みにしません**（申請中の件数をお知らせに出します）
2. 空欄のまま：定休日、この店舗で働く曜日ではない日、同じ人がほかの店舗に入っている日
3. **正社員（本人の「月の休日数」「週休」「この店舗で働く曜日」を入れていない人）**：**土日祝は原則出勤**にし、**月曜〜日曜の週ごとに、平日のシフト休を2日**入れます（設定 > チェック「平日の週のシフト休」。店舗ごと）
   - シフト休に数えるもの：通常休（手入力・AI）、承認済みの希望休、固定休、**定休日・臨時休業**。**有給は数えません**（有給をシフト休に変えることもしません）
   - その週にすでにシフト休が2日あれば足しません。手入力の休みが2日より多くても減らしません（お知らせに出します）
   - 前の月から続く週は、前の月に保存されているシフトも数えます。翌月に続く週は、この月に入る平日（月〜金）の数に合わせて減らします（例：平日が2日なら1日）
   - **月に2回の連休**（シフト休が2日以上続く所。定休日を含む・有給は含めない。3日続いても1回）ができるように、平日の休みを選びます（設定 > チェック「月の連休」）。月をまたぐ連休は、始まった日の月に数えます
   - 守れないとき（休める平日がない週・連休が足りない人・連勤の上限を超える所）は、休みや有給を変えずに、スタッフと日付・足りない条件をお知らせに出します。この人たちには、連勤を切るために休みを増やすことはしません
   - 「平日の週のシフト休」を0にすると、下の「月の休日数の目安」で作る今までのやり方になります
   それ以外の人（パート・本人の休日数や週休・働く曜日を入れた人）の休みの足し方：本人の「月の休日数」がある人はその日数まで。それ以外で、週休の人は月曜〜日曜で週休の日数まで（定休日・希望休・有給も休みに数える）。固定休がない人は「月の休日数の目安」まで。**土日祝には足しません**。人数に余裕のある日を選び、**連休（休みが2日以上続くところ）の回数が少ない人から順番に、連休になる日を選んで、連休が公平になるようにします**
4. 連勤の上限を超えないようにする（土日祝は休みにしないので、切れないときはお知らせ）
5. 勤務の日は、その日に合う勤務パターン（平日用／土日祝用）を選びます。日ごとに次の順で決めます
   1. **前日と違う番**（早番・遅番を交互に。前月の最後の日も見る。休みを挟んだら続きとは数えない。前日が休みなら、本人の少ないほうの番）
   2. 必要人数の不足が**実際に減るときだけ**番を変える（早早・遅遅にならない変え方を先に選ぶ）
   3. **早番が0人なら**、不足を増やさない範囲で1人を早番にする（店舗ごとに数え、別の店舗の人は数えない。前日が早番でない人を優先）
   4. その日の早番・遅番の人数と、一人ひとりの早番・遅番の回数をそろえる（早早・遅遅・不足・早番0人を増やさない入れ替えだけ。休みに挟まれた勤務のかたまりを、まるごと入れ替えることもある）
   - 希望休・有給・固定休・勤務曜日・使える勤務パターン・いつもの勤務・入力済みのマスは変えません
6. 作ったあとに確かめ、両立できないときは無理に入れず、理由を出します。確認画面の上に、次の4つを**別々に**表示します（問題がなければ「なし」）
   - **早番不足**：早番が0人の日と理由（例：早番の勤務パターンを使える人が、この日は出勤できない）
   - **連続勤務**：早早・遅遅（交互にできたはずなのに続いたもの）と理由（必要人数を満たすため・早番を1人確保するため など）
   - **必要人数不足**：日付・役割・人数と理由（**全員出勤しても足りない**＝必要人数の設定か、スタッフの人数・契約の曜日を確認／**休み（週休・希望休・有給など）の人がいるため**。自動作成の対象外の人がいるときは、そのことも）
   - **早番と遅番の回数の差**（3回以上）：必要人数・早番の確保・早早／遅遅を避けることを優先したとき
   - そのほか、休みが足りない週、連勤を切れない日、連休の回数の差（2回以上）も、お知らせに出ます
7. **制約あり（交互の対象外）**：その日に使える番が1つしかない人（片方の番の勤務パターンしかない人など）と、いつもの勤務で同じ番に決まっている人は、無理に変えず、確認画面の別の行とお知らせに「制約あり」として出します。交互にしたい場合は、両方の番の勤務パターンを登録するか、いつもの勤務を外してください

- 作成の確認画面のスタッフ別の表に、勤務・休み・**連休の回数**が出ます
- **パート**（設定 > スタッフの雇用形態）：契約（働く曜日・勤務パターンの時間・固定休・週休・いつもの勤務）を最優先します。正社員向けの「月の休日数の目安」「早番・遅番の交互」「連休の公平」は当てはめません（公平さは正社員どうしでそろえます）。**働く曜日も固定休の曜日も登録されていないパートは対象外**で、お知らせで登録を促します
- 正社員の「曜日ごとのいつもの勤務」は、早番・遅番の交互より優先します（交互にしたい人は、いつもの勤務の登録を外してください）

- 入力済みのマスは変えません。勤務パターンがない人は対象外です。戦力外の人は人数に数えません
- 自動で入れたマスは「自動作成を取り消す」で消せます（手で直したマスは残ります）
- **手入力の休み・有給は変えません**。確認画面に「手入力の休み・有給○マスはそのまま残します」と出ます
- 共有モードでは、入れる直前・取り消す直前に、保存先（Firebase）の最新の状態を確かめます。**ほかの端末で入れた休みなど、まだこの端末に届いていない入力は上書き・削除しません**（「ほかの端末で入力・手直し済みだった○マスは変えませんでした」と表示）。電波がなく確かめられないときは、何も入れずに知らせます
- 必要人数（設定 > 必要人数）を登録しておくと、足りない時間帯を優先して埋めます

### 当日の欠勤・休暇（子どもの発熱など、急な休み）

通常の希望休とは別に、**本人からの連絡（電話・LINE WORKS など）を受けて、店長が登録**します（事前の申請は要りません）。

1. シフト表で、その人のその日のマスを押し、「当日の欠勤・休暇」→「**欠勤・休暇を登録**」
2. **種類は店長が選びます**（緊急欠勤（種類は未確定）／年次有給休暇／子の看護等休暇／その他）。本人の申出・就業規則に沿って選んでください。アプリが自動で決めることはありません。理由は任意（50文字まで）
3. 登録すると状態は「**対応中**」。その日の**人員不足（時間帯・人数）**が表示されます。代わりの人は自動では入れません。同じ店舗の調整・他店舗からの応援・予約の変更などを検討し、シフト表で調整してください
4. 調整が終わったら「**確定する**」。取り消すと、もとのマスに戻ります

- マスには「急」の印が付きます（対応中は点線の枠）。年次有給休暇は「有給」、それ以外は「休み」のマスになります（古い版のアプリでも休み・有給として表示されます）
- シフト表の上の「**欠勤・急な休み（対応中 N件）**」で、その月の一覧（日付・スタッフ・種類・状態）を見られます。人員不足が残る日は「店長・代表への確認事項」として表示します
- **確定済みの月でも、欠勤・休暇の登録・変更・確定・取り消しだけはできます**（代わりの勤務の調整は「確定を取り消す」から）。共有モードで、確定した欠勤・休暇が変わると、スタッフの確定シフトを自動で作り直します
- スタッフの確定シフト・印刷・画像には、**確定した欠勤・休暇だけを「休」（年次有給休暇は印刷では「有」）**として出し、種類・理由は出しません。対応中のあいだは、もとのマスのままです
- ほかの人の希望休や確定済みのマスは変えません。AIシフト作成も、欠勤・休暇のマスには触れません。回数でスタッフを比べる機能はありません

**シフトを確定**：店舗・月ごとに確定します。確定した月は、**「確定を取り消す」を押すまで変更できません**（シフト・休憩・日付指定の社用）。申請の承認・却下はできますが、シフト表への反映は確定を取り消してから行います。印刷・画像のタイトルに「（確定）」が付きます。

### 確定シフトの公開（スタッフの「確定シフト」タブ）

- **「自分のシフトだけ」（11/5〜）**：縦に日付（1日〜月末）、横に時間の帯で表示します。出勤・社用の日は、始まりから終わりまで帯を引き、中に「9-18」の形で時間を出します（社用はしま模様）。休みは「休」（本人の承認済みの有給は「有」）、定休日は「定休」。上に「出勤 ○日・休み ○日」、時間の目盛りは、その月の自分のいちばん早い始まり〜いちばん遅い終わりです。中身は確定シフトの写しだけです。

管理者が「シフトを確定」すると、スタッフは申請画面の「**確定シフト**」タブで、**自分の所属店舗の今月・来月の確定シフト**（同じ店舗の全員分）を見られます。

- スタッフに見せるのは、確定したときに作る**公開用の写し**（Firestore の `publishedRosters`）だけです。入っているのは店舗名・月・スタッフの表示名と肩書きと St／As・日ごとの勤務時間／休／社用だけで、メールアドレス・備考・勤務条件・申請の中身は入りません
- ほかの人の有給は「休」と表示します（本人の承認済みの有給だけ「有」）
- 当日の欠勤・休暇は、確定したものだけを「休」で表示します（種類・理由は入りません）
- 「確定を取り消す」と、スタッフの画面からも消えます。直したあとにもう一度確定すると、新しい内容になります
- ほかの店舗の確定シフトは見えません（Firestore のルールでも止めています）

### 最初の1回だけ：実際の店舗・スタッフ・シフトを登録する

公開しているアプリのファイルには、実際の店舗名・スタッフ名・シフトは入っていません（初期データは「店舗A」「店舗B」などの架空の名前だけ）。
実際のデータは、管理者がログインしたあと、共有の保存場所（Firebase）にだけ登録します。

共有の保存場所が空のときだけ、ログイン後に次の2つが出ます。

1. **店舗名を入力して始める**：最初の店舗を作ります。スタッフ・シフト・ほかの店舗は、そのあと「設定」から登録します
2. **バックアップファイルから移す**：この端末で使っていたデータのバックアップファイルを選ぶと、内容を確認してから、写しをアップロードします
   - 店舗名は、空白を整えてアップロードします（例：「店舗 A」→「店舗A」、「Salon  1」→「Salon 1」）。店舗の id は変えません
   - 以前の形式のシフトには、店舗と月を書き込みます（今後、スタッフが自分の店舗だけを見る仕組みのため）

どちらも、すでにデータがあるときは、二重に登録しないよう、登録しません。
バックアップファイルは公開リポジトリ（GitHub）にアップロードしないでください。

### 勤怠（出勤・退勤・休憩）（11/10〜・v35・共有モード）

- **店舗の iPad**：設定 > 勤怠 で、店舗ごとに勤怠用のメールアドレスを登録する → iPad でそのアドレスでログインすると、**その店舗の打刻の画面だけ**になる（シフト表・設定は開けない）。横向きは画面いっぱい、スマホはスマホ用の画面
  - いちばん上に日付・曜日・時計と、苫小牧（胆振地方）の午前・午後の天気（気象庁の公開データ。気温は室蘭。読めないときは出さない）
  - その下に、今日の出勤予定の人（苗字だけ。同じ苗字は「佐藤（花）」のように名前の1文字）。シフトで休みの人は「休み」と出る
  - 名前を押す → 4けたの番号（PIN）→「出勤」「休憩開始」「休憩戻り」「退勤」。押すと短い演出。5回まちがえると1分待つ
  - 閉じるときは右下の「管理者」→ その iPad のアカウントのパスワード
- **画面（11/10〜・v37）**：上の左に店舗名と日付（曜日も同じ字）、真ん中に大きな時計、右端に天気（AM・PM。細い線の絵）。打刻のボタンを押すと「出勤しますか？」が出て、「はい」で打刻・「いいえ」でボタンの画面に戻る（押しまちがい対策）
- **管理者の「タブレット」タブ（11/11〜・v39）**：下のタブ「勤怠」の右。選んでいる店舗の、お店のタブレットと同じ画面を見本として見られる（今日の本物のスタッフ・天気・時計。名前 → 番号 → 打刻まで試せるが、本番の記録は書かない・番号はどれでも進む）。スマホを横向きにすると、画面の幅を iPad の横向きと同じ 1180 にして、上の見出し・下のタブを隠し、iPad と同じ画面で見られる。縦向きに戻すと元に戻る
- **起動のアニメーション（11/13〜・v41。v42 で、読み込みが終わってから最初から動かすように修正。v43 で、簡単ログインのロック画面（PIN）が出たときは止めておき、解除してから最初から動かすように修正）**：アプリを開いたときに1回、ロゴのマス・SHIFT・RENASCOR. が浮いてきて、画面が上へ抜ける（約2.9秒・押すとすぐ閉じる）。名札の線の色は、この端末で前にログインした役割（管理者＝オレンジ・幹部＝赤・スタッフ＝白。初めては出さない）。勤怠用 iPad・印刷では出さない。「視差効果を減らす」の人はふわっと消えるだけ（js/splash.js）
- **勤怠集計表（11/12〜・v40）**：会社の勤怠集計表の形（1人1枚・A4 縦）で PDF・Excel を出す。上に従業員番号・担当（店舗・職種）・氏名・対象期間、日ごとに日付・開始・終了・休憩・外出・労働・残業（1日〜末日の全部の行）、下に出勤日数・実働合計・残業合計・外出合計と、有給・遅刻・早退・早出などの回数。時間は小数第1位（四捨五入。月の合計は分のまま足してから四捨五入）。全員（1人1枚）か1人だけを選んで出せる
  - 労働＝終了−開始−休憩−外出（外出は管理者・幹部が「直す」で入れる。私用の外出として労働から引く）。残業＝労働−予定の労働（予定の時間−勤務パターンの休憩。パターンと合わない日は法定の休憩）。予定がない日は残業なし。遅刻・早退・早出は予定の開始・終了と比べて印をつける
  - 日をまたぐ勤務：出勤中の人の翌朝5時までの打刻は、出勤した日の勤務として「25:30」のように数える。iPad は0時〜5時に前の日の打刻も読み、前の日に出勤した人が退勤を押せる
  - スタッフの登録に「従業員番号」「氏名（集計表用）」を追加（空なら表示名）
  - 幹部は3店舗とも勤怠を見る・出力できる（直せるのは担当店舗だけ）。担当していない店舗の名前・予定（確定した月だけ）・有給の日は、管理者が作る集計表用の名簿（attendanceDirectory）から読む。確定シフトの写しを読めるのは担当店舗だけのまま
- **番号（PIN）**：スタッフ・幹部は自分のスマホの「アカウント・この端末の設定」で決める。忘れた人は、管理者が 設定 > 勤怠 で消して決め直す。番号そのものは保存しない（元に戻せない形だけ）
- **見る・直す**：管理者は下の「◷ 勤怠」、幹部は「勤怠」タブ（担当店舗だけ）。今日の様子・月の表・直す（直した記録は残る）
- **締め**：毎月最終日の 20:00 に締める。締めたあとは幹部は見るだけ（直せるのは管理者）。「集計表ができました」のお知らせが出る
- **集計表**：設定 > 勤怠 で決めたパスワードを入れると開ける（管理者・幹部）。**PDF・Excel** で出力できる
- **休み申請の「希望なし」**：受付期間に日を選ばずに「希望なしで送信」を押すと、「希望なし（送信済み）」になる
- Firestore のルール：kiosks・kioskDirectory・attendancePins・punchProofs・punches・punchEdits・attendanceLogs を追加（打刻は iPad から今日の分だけ・番号はルールで照合・直した記録は消せない）

## iPhone で使う・ホーム画面から開く

iPhone で使うには、アプリをインターネット上（GitHub Pages）に置きます。**GitHub に置くのはアプリのファイルだけで、シフトのデータは GitHub には送られません**（共有モードのデータは Firebase に保存します）。

### 公開（GitHub Pages）

家計簿アプリと同じ GitHub アカウントを使えます。

1. GitHub で新しいリポジトリ `shift-app` を作る（Public）
2. 「uploading an existing file」から、`shift-app` フォルダの**中身**をすべてドラッグ＆ドロップ →「Commit changes」
3. 「Settings」→「Pages」→ Branch を `main` / `(root)` にして「Save」
4. 数分後、`https://＜ユーザー名＞.github.io/shift-app/` で開けるようになります

### 追加したアプリを初めて開いたとき（11/5〜）

ホーム画面（iPhone）や Dock（Mac の Safari）に追加したアプリは、ブラウザとは別の保存場所を使います（ブラウザでのログインは引き継がれません）。
- 公開URLで開いたとき、まだモードを選んだことがなく、端末のデータが見本のまま（店舗A・店舗B）なら、**最初からログイン画面**で始まります。ログインすると、共有の保存場所（Firebase）の店舗・スタッフ・シフトが表示されます。
- 「この端末だけ」のモードで開いているときは、画面の上に「この端末だけのデータを表示しています」と「共有のデータを見る（ログイン）」が出ます。
- この端末だけのモードで実際に入力したことがある端末は、勝手に切り替えません。

### iPhone のホーム画面に追加

1. Safari で公開 URL を開く
2. 共有ボタン（□に↑）→「ホーム画面に追加」→「追加」
3. **以後はホーム画面の「シフト」アイコンから開く**（Safari のタブで開いたものとは、データが別になります）
- 一度開いたあとは、**電波がなくても開けます**（アプリのファイルを端末に保存しておく仕組みを入れています）
- ホーム画面から開くと、ブラウザがデータを消しにくくなります

### Mac で「アプリのように」開く

- **Safari**：公開 URL を開き、メニューの「ファイル」→「Dockに追加」
- **Chrome**：公開 URL を開き、アドレスバー右のインストールのアイコン（または「︙」→「保存と共有」→「ページをアプリとしてインストール」）

### 今のデータを公開版へ移す

`index.html` をダブルクリックして開いたアプリと、公開 URL のアプリは、ブラウザからは別のアプリ扱いです。

1. 今のアプリで「設定 > データ」→「バックアップを保存」
2. 公開 URL のアプリ（Mac・iPhone それぞれ）で「バックアップを読み込む」→「合体する」

### アプリを更新するとき

変更したファイルを GitHub の同じ場所にアップロードし直します。インターネットにつながっていれば、次に開いたときに新しい版になります。
